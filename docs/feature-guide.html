1 · Product in one page

Multi-channel sellers in China (Douyin, Taobao/Tmall, Xiaohongshu, Pinduoduo) see record sales but an empty bank account: fees, refunds, ads, influencer commissions, delivery and D15–D28 settlement delays hide the real cash position. It is a visibility problem, not a sales problem. Anchor example: ¥100,000 revenue → product 25k + ads 25k + commission 20k + delivery 12k + refunds 8k + platform fees 5k → real profit ¥5,000 (5%).

Owner questionEngineDeliversStatus
"How much do I really keep?"True Profit DetectiveProfit per product / campaign / channel + cost waterfallPhase 2–6
"Why did profit drop?"Driver ExplainerPeriod-over-period variance decomposed, ranked, with evidencePhase 2–6
"Will I run short of cash?"Survival Simulator30-day cash curve, what-if sliders, shortage day, alertsPhase 2–6

Non-negotiable architecture rule: authorised data → deterministic engine (the only source of numbers) → AI layer that parses questions & writes explanations (post-checked: any number not in the engine JSON is discarded → template fallback) → owner approves every financial action. The app must fully work with the LLM turned off.

4.2 Security implemented DONE

  • bcrypt (10 rounds) hashing · JWT HS256, 7-day expiry in httpOnly + SameSite=Lax + Secure-in-prod cookie
  • requireAuth / requireRole(...) middleware (role guard ready for Phase 4 endpoints)
  • helmet (CSP, HSTS, nosniff, frameguard…), strict CORS with credentials (WEB_ORIGIN), 1 MB JSON body cap
  • Two rate limiters: global 300/15 min · login 10 fails/15 min (express-rate-limit v7)
  • Central error handler: Zod→400 VALIDATION · Prisma P2002→409 · everything else→500 {error:"INTERNAL"} with no stack leakage; unknown routes → JSON 404
  • Append-only AuditLog on REGISTER / LOGIN / LOGIN_FAILED / LOGOUT with IP; cookies/authorization headers redacted in all logs
